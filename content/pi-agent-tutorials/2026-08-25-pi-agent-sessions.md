## 会话为什么是一棵树

普通聊天记录看起来是一条从上到下的直线。但编程任务经常需要回到更早的决定：方案 A 走不通时，你希望保留历史，又从某个节点尝试方案 B。

Pi 的会话文件采用 JSONL，并用树结构保存消息。`/tree` 不是简单地删除后面的消息，而是让当前工作分支切换到你选择的节点。

![Pi 会话从主线分叉，再恢复到不同方案的过程](/media/pi-agent-tutorials/pi-session-tree.svg)

## 会话保存在哪里

默认情况下，Pi 会把会话自动保存到：

```text
~/.pi/agent/sessions/
```

目录按工作路径组织，每个会话是一个 JSONL 文件。常用启动方式：

```bash
pi -c                   # 继续当前项目最近的会话
pi -r                   # 浏览并选择历史会话
pi --name "修复搜索"    # 给新会话命名
pi --no-session         # 临时对话，不保存
```

进入交互界面后，使用 `/session` 查看文件、会话 ID、消息数、Token 和成本。

## `/tree`、`/fork` 与 `/clone` 的区别

### `/tree`

查看当前会话树，并跳转到其中任意节点继续。适合在一个任务内回到旧决策，保留多个实验分支。

### `/fork`

从较早的用户消息创建一个新的会话文件。适合“保留原任务不动，另开一份完全独立的尝试”。

### `/clone`

把当前活跃分支复制为新会话。适合在已经整理好的上下文基础上，开始一个相邻但不同的任务。

可以把它们理解为：`/tree` 在同一棵树上换枝，`/fork` 从旧节点栽一棵新树，`/clone` 把当前这根枝复制成新树。

## 什么是上下文压缩

模型的上下文窗口有限。会话变长后，Pi 会把较早内容总结为一条压缩记录，同时保留最近消息。你也可以手动执行：

```text
/compact
```

或者附加希望保留的重点：

```text
/compact 保留已经确认的根因、修改过的文件、失败过的方案和剩余测试
```

压缩不会让历史会话文件消失；它改变的是接下来送进模型的上下文。源码中的 `AgentSession` 会在接近阈值、溢出或手动触发时准备压缩，并把摘要继续加入会话树。

## 长任务的实用节奏

建议把大任务按下面节奏推进：

1. 启动时用 `--name` 明确任务；
2. 完成根因分析后，让 Pi 总结确认过的事实；
3. 方案发生分歧时使用 `/tree`；
4. 进入实现前建立 Git 检查点；
5. 上下文很长时手动 `/compact`，明确必须保留的事实；
6. 结束前让 Pi 输出改动、验证和未完成项，再用 `/export` 导出 HTML（如有需要）。

## 不要把会话当作唯一状态

会话可以帮助模型记住过程，但真正应当长期保存的事实仍应该回到项目里：

- 代码和测试进入 Git；
- 项目规则进入 `AGENTS.md`；
- 架构决定进入文档或 ADR；
- 临时验证结果可以写进任务记录。

这样即使换模型、换会话或发生压缩，项目仍然拥有可验证的事实来源。
